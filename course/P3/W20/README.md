## 高级工程师面试覆盖

- **原理与推导**：给定含 `N` 个 AST 节点、`E` 条引用边的程序，推导解析、名字解析与类型检查的时间/空间复杂度，并解释为何多趟 Frontend 仍可保持近线性。
- **源码与产物**：沿 Clang `Parser`、`Sema`、`ASTContext` 到 LLVM IR module，再到优化流水线与 target backend，辨认 AST、符号表、类型信息和生成 IR 各自承载的语义。
- **性能与实验**：分别测量 parse、semantic analysis、optimization、code generation 时间；固定输入与目标架构，对照优化级别，避免把编译时增长误判为运行时收益。
- **正确性与故障**：以作用域遮蔽、重载解析歧义、未定义行为被错误保留为例，说明 Frontend 诊断与 IR 语义不变量；用源位置诊断、AST dump 和 IR verifier 定位阶段归属。
- **系统设计与评审**：评审“丰富 AST 直接 CodeGen”与“稳定 IR 分层解耦 Frontend/Backend”的演进成本、优化复用、诊断质量与目标平台扩展性。

## 与既有经验的连接

- **数据库内核**：Frontend/AST/IR/Optimizer/Backend 对应 SQL parser、绑定后的语法树、逻辑计划、优化器和执行计划；类比止于阶段职责，编程语言的类型与副作用语义不等同于 SQL 的三值逻辑和集合语义。
- **存储引擎**：符号表与 AST 节点索引类似元数据目录帮助定位对象；它们都是编译期易失结构，不具备页、WAL、崩溃恢复或持久格式兼容性。
- **计算引擎**：Frontend 到 Backend 的阶段化与逻辑计划到物理算子的转换同构；但机器指令选择受 ABI/寄存器约束，不能照搬算子选择规则。
- **分布式系统**：清晰的 IR 契约像服务接口，可隔离前后端版本演进；但单进程编译阶段没有网络分区、重试和副本一致性语义。
- **可观测性**：源位置、AST dump、IR dump 与分阶段耗时构成编译链路的可追踪性；它们解释编译决策，却不能替代生成程序的运行期 Trace。
