## 高级工程师面试覆盖

- **原理与推导**：由到达率 lambda、服务时间 S、并发 C 与目标分位延迟推导利用率/容量余量，并以错误预算和单位 token 成本评估扩容。
- **源码与产物**：读取服务 SLO/SLI、autoscaler policy、负载生成配置与故障注入/恢复时间线，能把配置项映射到控制环。
- **性能与实验**：以 TTFT/TPOT p99、goodput、错误率、恢复时间和 cost/token 为指标，对照流量形态、副本数、扩缩容阈值与故障类型。
- **正确性与故障**：守住 SLI 口径、负载分布与成本边界一致；用错误预算、队列、扩容事件和注入日志诊断测量漂移、振荡或恢复失败。
- **系统设计与评审**：在冗余容量、成本、冷启动、弹性稳定性与恢复目标间给出可量化方案。

## 与既有经验的连接

- **数据库内核**：admission 与容量保护类似查询并发控制；但生成式请求长度重尾，平均 QPS 不能代表负载。
- **存储引擎**：恢复点/恢复时间目标类比成立；但模型服务状态多可重建，用户会话和缓存是否持久化需单独界定。
- **计算引擎**：弹性伸缩像动态 slot 管理；但 GPU 模型加载冷启动使控制环远慢于普通 task 调度。
- **分布式系统**：故障注入验证冗余与恢复路径；但控制面健康不等于端到端 SLO 在错误预算内。
- **可观测性**：SLI、流量、容量、成本与注入事件必须同口径关联；p50 改善不能抵消 p99 或错误预算恶化。
