# W63 · 论文复现、对照实验、回归审计、开源贡献准备

## 本课目的

围绕 **论文复现、对照实验、回归审计、开源贡献准备** 建立可用于高级 AI Infra 工程判断的知识模型。重点是理解原理、实现位置、性能边界和失效条件，不训练脱离 Agent 的机械操作熟练度。

## 固定 Scope

本课只覆盖以下已经确定的主题：

- 论文复现
- 对照实验
- 回归审计
- 开源贡献准备

这些条目是本课内容边界。授课 Agent 可以补充解释、例子和一手证据，但不得新增课程主题、删除条目或把后续周内容提前替代本课。

## 掌握目标

- 能用自己的语言解释本课全部 Scope，说明各概念之间的因果关系。
- 能指出真实系统中承载这些机制的组件、源码位置或运行证据。
- 能说明关键性能、正确性、可靠性或成本权衡，以及至少一种失效条件。
- 能分别把本课知识连接到数据库内核、存储引擎、计算引擎、分布式系统和可观测性经验，并指出每个类比的失效边界。

## 高级工程师面试覆盖

- **原理与推导**：从论文主张提取效应量、方差和样本数，计算 speedup、置信区间并区分统计显著与工程显著。
- **源码与产物**：把论文算法映射到固定 revision 的 commit/file/function，形成最小补丁、测试与可审查的实验原始产物。
- **性能与实验**：固定硬件、软件、输入和统计口径，设计 baseline/ablation，多次测量并报告中位数、尾部和方差。
- **正确性与故障**：守住基线等价、无数据泄漏、无 cherry-pick 和回归可复现；用环境 manifest、seed、raw result 与 git diff 审计。
- **系统设计与评审**：决定复现偏差是实现、环境还是论文限制，并将贡献拆成可维护、可回滚且范围明确的变更。

## 与既有经验的连接

- **数据库内核**：回归与 differential testing 类比成立；但模型/Kernel 还需数值容差和随机性控制。
- **存储引擎**：原始结果与 revision 像可追溯快照；但索引文件本身不是实验数据证据。
- **计算引擎**：ablation 类似隔离优化 pass；但多个优化相互作用时不能简单相加归因。
- **分布式系统**：复现实验需固定拓扑和故障条件；一次成功运行不能证明稳定性。
- **可观测性**：raw metric、trace、profile 与结论要可回链；只保留截图或汇总数无法审计。
