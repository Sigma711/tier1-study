# W62 · Platform：部署、可观测、压测、资源控制

围绕 **Platform：部署、可观测、压测、资源控制** 建立可用于高级 AI Infra 工程判断的知识模型。重点是理解原理、实现位置、性能边界和失效条件，不训练脱离 Agent 的机械操作熟练度。

## 掌握目标

- 能用自己的语言解释本课全部 Scope，说明各概念之间的因果关系。
- 能指出真实系统中承载这些机制的组件、源码位置或运行证据。
- 能说明关键性能、正确性、可靠性或成本权衡，以及至少一种失效条件。
- 能分别把本课知识连接到数据库内核、存储引擎、计算引擎、分布式系统和可观测性经验，并指出每个类比的失效边界。

## 高级工程师面试覆盖

- **原理与推导**：由目标并发、服务率、p99 SLO、GPU 容量和冗余系数推导副本数、资源 limit 与压测饱和点。
- **源码与产物**：审查 Kubernetes Deployment/Service、GPU resource request、metrics/trace schema 与 load-generator workload 配置。
- **性能与实验**：以 goodput、TTFT/TPOT p99、错误率、GPU/KV 利用率和 cost/token 对照副本、并发、资源 limit 与发布版本。
- **正确性与故障**：守住镜像/模型 revision、配置、指标标签和租户资源绑定；用 rollout、pod event、trace 与压测原始结果诊断。
- **系统设计与评审**：权衡部署可回滚性、信号开销、压测真实性、资源隔离和成本，定义上线/回退门禁。

## 与既有经验的连接

- **数据库内核**：资源控制与 workload group 类似；但模型版本和 GPU 拓扑必须成为准入维度。
- **存储引擎**：部署制品/模型版本像不可变 snapshot；但运行缓存不应被误当成发布事实。
- **计算引擎**：副本和 worker pool 类比执行 slot；但在线压测关注尾延迟和过载，不只是批吞吐。
- **分布式系统**：rollout/health/rollback 类比成立；但 Kubernetes Ready 不证明模型语义或 SLO。
- **可观测性**：指标、日志、Trace 和压测 workload 必须绑定 revision；没有流量上下文的 GPU 利用率无法验收。
