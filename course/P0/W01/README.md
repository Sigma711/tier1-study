## 高级工程师面试覆盖

- **原理与推导**：能沿“模型算子 → 框架调度 → 编译/Kernel → GPU”解释执行链，并用延迟 \(T=\max(T_{compute},T_{memory})+T_{overhead}\)、吞吐量和 Little's Law 区分容量、利用率与排队。
- **源码与产物**：能从 PyTorch `Tensor/Dispatcher` 追到 ATen/CUDA Kernel，并识别 FX/StableHLO 等图或 IR 是哪一层产物，而不是把 Python 调用当作 GPU 执行。
- **性能与实验**：能分别定义训练吞吐、TTFT、TPOT、tokens/s、MFU 与显存峰值；对照实验固定模型、精度、Shape、批量、并发、预热和统计分位数。
- **正确性与故障**：能用输出误差、Profiler 时间线、Kernel launch 与设备利用率证据诊断 CPU 瓶颈、同步空洞、OOM、数值异常和“高利用率但低有效吞吐”。
- **系统设计与评审**：能按训练/在线推理/离线推理目标选择吞吐优先或尾延迟优先架构，并说明能力测评如何避免把工具熟练度误判为系统判断力。

## 与既有经验的连接

- **数据库内核**：模型图到 Kernel 的链路像 SQL 到物理算子的执行路径，成立于分层与代价归因；失效于张量数值语义、GPU 并行和训练状态并非关系代数。
- **存储引擎**：参数、Activation 与缓存的容量核算像页/缓存预算，成立于工作集和带宽约束；失效于它们通常是易失 GPU 状态，不具备事务持久性。
- **计算引擎**：算子图、调度和端到端瓶颈可类比 DAG 执行，成立于关键路径分析；失效于 GPU Kernel 的 SIMT、数值精度和设备同步约束。
- **分布式系统**：吞吐、排队和故障域方法可用于 AI 服务容量设计；失效于本课单设备执行链尚不能推出跨节点一致性与通信语义。
- **可观测性**：metrics/logs/traces 与 Profiler 共同组成证据链；失效边界是指标相关性不证明某个 Kernel 或软件层是根因。
